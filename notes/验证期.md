# 验证期

各阶段写 JSON，再由 `valuation/workbook` 一次出 Excel。页面、Temporal、审核卡 UI 不做。最新命令以仓库根目录 `README.md` 为准。

## 怎么跑

```bash
cd 估值模型
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt

# 完整活数据建模
.venv/bin/python -m valuation --ticker 300750 --name 宁德时代

# 改 JSON 后只重编译，不重跑各阶段
.venv/bin/python -m valuation --resume <run_id> --rebuild-only
```

产物在 `output/<日期>_<代码>/`：

- 阶段 JSON：facts / 拆分 / 各分部 forecast / 费率 / 同业 / snapshot / summary_notes
- `<股票名>_估值模型.xlsx`：7 tab 公式工作簿
- `research_dossier.md`
- `certify.json`

## 编排（已实现）

```text
historical_financials → segment_split → [审核点]
historical_fill
segment_research × 每个分部 → [审核点]
operating_cost → peer_valuation → [审核点]
research_dossier → workbook.build → workbook.certify
```

分析师先写 `research_dossier.md` 再抽出 `summary_notes.json`，总结叙述区读这份封面。`--rebuild-only` 只重编表，不重写底稿。不加 `--auto-approve` 时，改完 JSON 再 `--resume`。

`valuation/comein` 是进程自己的 MCP 客户端（SSE / Streamable HTTP），不经过 Cursor 的 `CallDynamicTool`。

```bash
.venv/bin/python -m valuation.comein ping
```

`--ticker/--name` 时 `historical_financials` 会按科目表分表拉利润表 / 资产负债表，核心行缺了失败，扩展行能取则写入。确认拆分名单后，`historical_fill` 由模型按计划补搜并拍出历史分部收入，代码只校验加总对得上营业收入。`segment_research` 按分部先搜集内资/外资/纪要/点评，再由模型给出该行预测。`operating_cost` 由公司级 agent 按已算好的历史轨迹检索卖方毛利/费用后落假设。`peer_valuation` 先拉本公司一致预期，再提名同业、取 pricePerformance 的 peForward 后只分核心。

## 怎样算达标

- 必须：7 tab 公式 xlsx、量价/兜底模板正确、certify 过
- 应该：改 `final_forecast` 后 `--rebuild-only` 能出新表
- 不验收：页面
