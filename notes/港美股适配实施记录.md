## 已实现

- 按证券代码分流：六位 A 股代码保持旧路径；四/五位或 HK 前后缀识别港股；字母代码识别美股。
- 港股接受经筛选的“财务指标”来源金额；港美股独立处理科目名称、美元/港元金额、实际财年截止日和缺失值，不放宽 A 股原有解析。
- 从进门年度公告补取原始财报，保存请求、原始片段和逐字段来源。完整损益表可直接解析，解决已验证的供应商 SG&A、税项等字段口径问题；模型提取的其他补充值检查原文引用、年度、单位和勾稽。
- 支持分开的销售/管理/研发、SG&A 加研发、销售与管理整体披露、研发包含于管理费用、综合经营费用等布局。预测和工作簿仅扣除该布局的有效费用行。
- 使用“营业利润 + 非经营净收益 = 税前利润”的港美股利润桥。保留原始 EBIT 语义边界，不把营业利润强行当作 EBIT。
- 财务币种和交易币种分别保存。不同币种的目标价通过有来源、日期和方向的汇率换算。默认读取 ECB 参考汇率；缺失、未来或过期汇率不能继续估值。
- 当前股数、历史加权股数、普通股与 ADS 基础分别保存。EPS 为零不会导致历史提取失败；没有核实 ADS 基础时不输出目标价。
- 一致预期只有财年、币种、金额倍率、报告/调整口径及每股基础明确时才纳入比较。
- 不完整财务仍保存为 `facts.json`、`financial_coverage.json` 和历史工作簿；完整流程在历史财务后检查是否可以继续。

原有 60 项测试通过，新增 18 项跨市场测试通过，共 78 项。新增测试覆盖真实接口样本、币种和期间隔离、原始报表解析、费用不重复扣除、零 EPS、ADS 股数、汇率方向及日期、一致预期口径，以及港股、美股两种费用布局的七张工作表构建和校验。

A 股以科大讯飞既有完整建模产物做回归：改动前后七张工作表的所有非空单元格数值、公式、数字格式、样式编号及合并区域完全一致，原有工作簿校验通过。原始 A 股金额解析行为也保持不变。

以下两例通过了实际 `historical_financials.write` 入口的联网验证，历史期间均为 FY2023—FY2025，必需字段缺口及未解决的核心口径冲突均为零：

|---|---|---|---|

这些目录是历史财务验证产物，并未为两家公司运行整套分部研究及投资判断。下游七张工作表以独立测试中的合成预测假设验证，不能把测试预测当成公司研究结论。

## 使用方式

```bash
# 只运行第一步，适合检查数据覆盖
.venv/bin/python -m valuation --ticker 09992 --name 泡泡玛特 --historical-only
.venv/bin/python -m valuation --ticker AAPL --name 苹果 --historical-only

# 完整流程：通过财务完整性检查后继续原有研究阶段
.venv/bin/python -m valuation --ticker 09992 --name 泡泡玛特

# 手工核对后补充公告数据或股数基础
.venv/bin/python -m valuation --ticker 09992 --name 泡泡玛特 --financial-supplement 补充.json

# 回归检查，无须联网
.venv/bin/python -m unittest discover -s valuation/tests
```

已有后续预测的目录不能直接更换财报补充并复用旧预测卡；应在新建模中传入补充文件。仅完成历史财务、停在补缺阶段的目录可用 `--resume` 配合补充文件继续。

## 补充文件契约

顶层包括 `full_code`、`currency`、`currency_evidence`、`expense_profile`、`share_basis`、`periods`，跨币种时还包括 `fx`。实际可参考上述两个验证目录中的 `financial_supplement.json`。

- `currency_evidence`、`expense_profile`、`share_basis` 需要 `source_url` 和原文 `evidence`。
- `expense_profile.layout` 可为 `separate`、`sga_rd`、`sales_admin`、`sales_admin_embedded_rd` 或 `combined`。不能仅因研发取不到就声明其为零或含在管理费用中。
- `share_basis.instrument` 和 `current_shares_basis` 明确为 `ordinary` 或 `ADS`；ADS 还需 `ordinary_per_ads`。`historical_eps_basis` 记录历史每股收益基础。
- `periods` 使用 `2025A` 等财年键，并写实际 `period_end`；必须与接口年度截止日一致。
- 每个 `values` 单元格写 `value`、`currency`、`scale`、`source_url`、`evidence`。金额倍率固定为 100000000，每股值为 1，百万股值为 1000000；数值使用相应倍率后的结果。
- `fx` 写 `quote_per_model`、`from`、`to`、`as_of`、`source`，含义为“每一单位财务币种对应多少交易币种”。不能倒置。

## 当前边界

这次验证证明已覆盖上述实际样本和相关数据结构，并不等于每一家港美股都能自动形成完整估值。公告检索未命中、来源单位缺失、费用布局未证实、ADS 股数基础未核实等情况，会保留明确缺口并停止依赖这些数据的估值。

阿里巴巴美股等由供应商转换为美元、原始报告采用其他币种的案例，未换汇的不同币种金额会被隔离；需要统一到有证据支持的财务币种，并核对 ADS 基础。银行、保险等特殊行业也不能直接套用普通工商企业的费用布局。
