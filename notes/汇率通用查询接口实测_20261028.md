# 汇率通用查询接口实测

测试日期：2026-10-28（北京时间）。使用项目已配置的进门 MCP 服务真实调用；未修改估值程序、已有模型输入或工作簿。

## 结论

可采用通用的“搜索候选、核验口径、逐条取数、归一化、按同日交叉计算”流程。取数接口每次只返回一条序列。直接把 index_name 写成“汇率”，本次会自动选中美元兑人民币，不会返回所有汇率。

完成 8 次搜索和 20 次取数。搜索共返回 160 条候选记录，按 ID 去重为 131 条；这些候选包含不同频率和非即期序列，不能视为全部合格汇率，也不能视为全库完整目录。

## 查询设计

通用发现查询：

```json
{
  "topic": "汇率",
  "freq": "日"
}
```

保持当前官方中间价政策的发现查询：

```json
{
  "topic": "人民币汇率中间价",
  "freq": "日",
  "data_source": "中国外汇交易中心"
}
```

按模型实际需要的币种补充搜索，topic 模板为 `{币种中文名}汇率中间价`；本次用瑞士法郎、新加坡元验证，均能发现此前宽泛查询未包含的相应官方日频序列。

取数参数从筛选后的候选原样生成，不固定指标名单：

```json
{
  "index_name": "<候选.indexName>",
  "data_source": "<候选.dataSource>",
  "start": "202610",
  "end": "202610"
}
```

## 重要边界

- 本次每次搜索均返回20条候选；工具说明没有提供分页、总量或全库枚举能力，不能保证一次搜索列全。应采用宽泛发现加按需币种搜索。
- freq 和 data_source 对搜索是语义约束，结果仍混入其他频率、其他来源、远期、汇率指数及外汇成交额；必须本地硬筛选，取数后再次核验返回元信息。
- 原始指标可能缺少独立的单位字段。日元指标明确为100日元兑人民币，应将原始报价除以100；不能统一按1单位解读。人民币兑韩元、卢布等须识别相反方向。
- 部分响应包含指定月份以外的日期，须按请求区间、基准日和14天时效窗口本地截取。元信息终止日期也可能落后于实际返回数据，选择日期应依据数据行并记录差异。
- 香港金融管理局的“中国香港:美元兑港元”查询2026年10月时返回成功，但没有任何数据行；不能把业务成功码当成数据可用。
- “中间价:人民币兑比索”虽有数值，但名称没有明确哪一种比索，元信息亦未确认，测试中保留原始记录，未自动映射成某个ISO币种。
- 直接美元兑港元、人民币交叉中间价、不同央行参考价具有不同来源、时点与口径。测试发现的替代来源不应自动改写当前模型的来源政策。
