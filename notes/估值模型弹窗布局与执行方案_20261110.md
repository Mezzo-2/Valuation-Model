# 估值模型弹窗布局与执行方案

2026-11-10

用户从个股页打开估值窗口，确认当前股票后点击「开始建模」。每次新任务都运行完整流水线，自动完成 PE、DCF、研究底稿、Excel 编表与验表。任务完成后，结果窗口直接用平台现有 Excel 组件打开本次生成的工作簿。

## 1. 入口和打开规则

沿用 [Demo](../demo.html) 的两个入口。「估值模型」紧挨「最新业绩」标题右侧，「更多」靠右。行情栏的同名入口紧挨「−自选」左侧，并跟随行情栏的紧凑状态。

两个入口共用同一个窗口和任务记录。每次打开时将个股页的证券名称、市场和证券代码绑定到窗口。建模对象以提交时的证券标识为准，用户切换到其他股票后，可在原个股页继续查看任务。

| 当前股票的状态 | 打开时显示 | 可用操作 |
| --- | --- | --- |
| 首次建模 | 启动窗口 | 开始建模 |
| 排队或运行中 | 任务进度 | 收起、查看上一版 Excel（如有） |
| 最近任务中断 | 中断阶段和可处理的原因 | 继续建模、查看上一版 Excel（如有） |
| 已有通过验表的结果，且无更新中的任务 | 最近通过验表的 Excel | 查看底稿、查看校验、下载 Excel、重新建模 |

## 2. 窗口布局

### 2.1 启动窗口

桌面居中，建议宽 560 px，小窗口留至少 16 px 边距。标题和关闭按钮位于顶部。主体只有股票身份、流程概述和交付物，底部右对齐主按钮。

```text
┌───────────────────────────────────────────────┐
│  估值模型                                  ×  │
│                                               │
│  瑞芯微   603893.SH                           │
│  自动完成财务取数、经营预测、PE 与 DCF 估值    │
│  产出 Excel 工作簿、研究底稿和校验报告          │
│                                               │
│                         [关闭]  [开始建模]    │
└───────────────────────────────────────────────┘
```

「开始建模」直接提交完整任务。提交期间按钮显示「正在启动」并禁用，服务端返回任务后原地切到进度。行情快照时间、历史期和预测期由本次流程确定，取到后在结果页展示。方法、预测年数和估值参数由项目默认流程决定。

### 2.2 任务进度窗口

建议宽 640 px，顶部固定股票和任务状态，中间为纵向步骤，底部为操作区。业务步骤对应真实的后台阶段，合并步骤可以展开查看各子阶段状态。

```text
┌─────────────────────────────────────────────────┐
│  估值模型  瑞芯微 · 603893.SH                ×   │
│  建模中                                         │
│                                                 │
│  ✓  财报与行情                                  │
│  ✓  主营拆分与历史回填                          │
│  ●  分部研究、收入与成本预测         进行中     │
│  ○  PE 与 DCF 估值                              │
│  ○  研究底稿                                    │
│  ○  Excel 编表与验表                            │
│                                                 │
│                       [查看上一版 Excel] [收起] │
└─────────────────────────────────────────────────┘
```

排队时显示「等待开始」，运行时显示正在执行的阶段。关闭或收起窗口后任务继续执行，重新打开恢复进度。中断时在对应步骤下展示具体原因，主按钮改为「继续建模」，复用已完成阶段。首次建模时，底部只有「收起」。

### 2.3 结果窗口

建议宽度为 `min(1440px, calc(100vw - 48px))`，高度为 `calc(100dvh - 64px)`，提供最大化操作。窗口外层只保留标题、产物切换和文件操作，Excel 组件占满下方内容区。

```text
┌─────────────────────────────────────────────────────────────────────┐
│  估值模型 · 瑞芯微 603893.SH                         [最大化] [关闭] │
│  数据快照 2026-11-09 10:39    计算校验通过                           │
│  [Excel 工作簿] [研究底稿] [校验报告]       [重新建模] [下载 Excel]  │
├─────────────────────────────────────────────────────────────────────┤
│                                                                     │
│                      平台 Excel 组件                               │
│                  打开 瑞芯微_估值模型.xlsx                           │
│                                                                     │
│        默认定位「总结」，使用组件自带的工作表导航和浏览控件           │
│                                                                     │
└─────────────────────────────────────────────────────────────────────┘
```

- 「Excel 工作簿」是完成态的默认视图，直接打开本次运行的原始文件。「总结」包含估值概览、财务预测、关键经营假设和投资逻辑。其他工作表沿用真实文件顺序，包括主营业务拆分、收入预测、运营成本预测、利润表预测、相对估值预测、DCF估值和历史财务数据。
- 「研究底稿」在同一内容区呈现本次 `research_dossier.md`，支持按章节浏览。「校验报告」呈现同一次运行的 `certify.json`，区分计算、格式和数据提示。切回 Excel 时恢复之前的工作表和浏览位置，优先复用同一组件实例。
- 「下载 Excel」与组件打开同一版本的文件。「重新建模」发起独立的新任务。查看旧版时，页面保留旧版的数据快照和状态，新版就绪后提供「查看本次 Excel」，由用户切换。
- Excel 组件加载失败时显示「重试打开」，并提供当前版本的「下载 Excel」。关闭窗口后将焦点还给触发入口。任务运行中的收起按钮和关闭按钮执行相同的界面行为。

## 3. 接入现有流水线

新任务由后端按证券标识调用 [项目入口](../valuation/pipeline.py) 的默认完整模式。当前 CLI 等价命令为 `python -m valuation --ticker 603893 --name 瑞芯微`。服务端将页面证券标识按市场适配成 CLI 支持的代码格式，使用参数列表调用进程。页面传递证券标识即可。

| 进度窗口文案 | 对应阶段 | 阶段输出 |
| --- | --- | --- |
| 财报与行情 | `historical_financials` | 财务事实、公司资料、行情快照 |
| 主营拆分与历史回填 | `segment_split`、`historical_fill` | 分部口径和历史分部收入 |
| 分部研究、收入与成本预测 | `segment_research`、`operating_cost` | 分部研究、预测卡和成本假设 |
| PE 与 DCF 估值 | `peer_valuation`、`dcf` | 一致预期、同业与目标 PE、DCF 输入及计算结果 |
| 研究底稿 | `research_dossier` | 研究底稿、快照、Excel 总结所需文稿 |
| Excel 编表与验表 | `build`、`certify` | 带公式的 Excel 和校验报告 |

一组内所有子阶段成功才标记为完成。DCF 阶段遇到模型已支持的输入缺口或不适用情形时，继续走后续编表和验表，在 DCF 工作表及结果区提示具体缺口。

## 4. 任务与产物接口

以下为建议接口，接入时沿用平台已有任务、存储与权限约定。

| 操作 | 最小输入与返回 | 行为 |
| --- | --- | --- |
| 查询个股估值状态 | 证券标识 → 当前任务、最近已校验版本 | 两个入口用同一次查询决定落点 |
| 开始建模 | 证券标识、幂等标识 → 任务 ID | 同一权限范围与证券仅允许一个运行中的任务，重复提交返回原任务 |
| 查询进度 | 任务 ID → 状态、当前阶段、已完成阶段、中断原因 | 窗口可使用平台现有任务订阅或轮询 |
| 继续建模 | 任务 ID → 原任务 ID | Worker 使用完整 `run_id` 调用现有 `--resume` |
| 查询产物 | 已校验版本 ID → Excel 文件标识、底稿、校验报告、快照时间 | 组件打开和下载均用该版本的文件标识 |

- 服务端绑定平台任务 ID、项目 `run_id` 与独立运行目录。接入并发前，为每次运行分配唯一目录，处理当前 CLI 按秒生成目录名时可能出现的冲突。
- 现有 `run_state.json` 的 `current_stage` 在步骤完成后更新。Worker 需采集阶段开始事件、已完成阶段和进程退出结果，用来显示正在执行的步骤与失败原因。继续建模前检查是否仍有进程持有该任务。
- 发布结果同时校验进程成功退出、`certify` 完成、校验报告无计算失败，以及三个产物存在。格式和数据提示按报告内容展示。计算校验失败时展示错误明细，修正受影响的阶段后重新编表、验表。已校验的上一版仍可打开。
- 文件登记按同一运行目录收集 `<公司名>_估值模型.xlsx`、`research_dossier.md` 和 `certify.json`。用 `facts.json` 的 `as_of` 显示数据快照，完成时间单独记录。文件读取、底稿和下载沿用同一版本的访问权限。

## 5. 实施顺序

1. **先打通 Excel 完成态。** 用[已完成的瑞芯微工作簿](../output/20261109_103934_603893/瑞芯微_估值模型.xlsx)验证平台组件的文件打开契约、默认「总结」页、工作表切换与下载。源文件保留公式，未保存公式结果缓存。联调时检查组件能否打开后重算并正确显示跨表结果，尤其是「总结」里的相对估值目标价、EPS 和 DCF 每股价值。
2. **接入任务服务。** 打通完整模式提交、阶段状态、并发去重、进程中断识别和原任务续跑。先使用现有流水线的产物与校验结果完成发布。
3. **连接两个页面入口。** 以 Demo 的入口位置和样式为基准，在平台个股页接入同一个弹窗组件。实现启动、进度、结果三个状态，以及收起重开、上一版查看和新版就绪提示。底稿和校验报告与 Excel 一起接入。
4. **用真实证券验收。** 从瑞芯微入口走完一次完整任务，对照本次生成的工作簿、[研究底稿示例](../output/20261109_103934_603893/research_dossier.md)和[验表报告示例](../output/20261109_103934_603893/certify.json)。再选一只港股或美股验证代码、币种和文件展示。

## 6. 验收标准

- 两个入口对同一股票显示同一任务。「开始建模」是首次打开时唯一的建模操作。提交后进入完整流程，完成态默认打开 Excel「总结」。
- 重复点击、从另一个入口打开以及页面刷新均复用当前任务。切换股票后，证券名称、进度和结果与各自任务匹配。
- 任务收起后可重开，进度与实际阶段一致。模拟一个阶段失败，重试接着执行未完成阶段。
- 计算校验通过后能打开原始 Excel，切换 8 张真实工作表，查看有效跨表公式结果。通过同一工具栏打开对应底稿与校验报告，并下载同版本文件。
- DCF 有数据缺口时显示该缺口。新版失败时仍能查看上次已校验的结果，新版成功时可主动切换。
